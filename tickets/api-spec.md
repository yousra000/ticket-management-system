# API Specification — Stage 1

Base URL (local): `http://localhost:8000`
Interactive documentation (generated by FastAPI): `http://localhost:8000/docs`

All request and response bodies are JSON. Timestamps are ISO 8601 in UTC (ending in `Z`).

## Ticket object
```json
{
  "id": 1,
  "title": "Login page returns 500",
  "description": "Happens after submitting the form",
  "status": "open",
  "priority": "high",
  "assignee": "sara",
  "created_at": "2026-10-24T13:20:19Z"
}
```

## Endpoints

### GET /api/health
Checks that the API can query MySQL.

| Response | Status | Body |
|----------|--------|------|
| Healthy | 200 | `{"status":"ok","database":"ok"}` |
| Database unreachable | 503 | `{"status":"error","database":"unavailable"}` |

### GET /api/tickets
Lists tickets, newest first.

Query parameters (optional):
- `status` — one of `open`, `in_progress`, `resolved`, `closed`
- `priority` — one of `low`, `medium`, `high`, `critical`

Responses: 200 with an array of tickets; 422 for an invalid filter value.

### POST /api/tickets
Creates a ticket.

Request body:
```json
{
  "title": "Login page returns 500",
  "description": "Happens after submitting the form",
  "status": "open",
  "priority": "high",
  "assignee": "sara"
}
```
Only `title` is required. Defaults: `status` = `open`, `priority` = `medium`.

Responses: 201 with the created ticket; 422 for validation errors; 503 if the database is unavailable.

### GET /api/tickets/{id}
Returns one ticket. Responses: 200, or 404 `{"detail":"Ticket 9 not found"}`.

### PUT /api/tickets/{id}
Replaces all editable fields of a ticket. The request body has the same shape and rules as POST. Fields left out become their default values (for example, `description` becomes `null`).

Responses: 200 with the updated ticket; 404 if missing; 422 for invalid data (the ticket is not changed).

### DELETE /api/tickets/{id}
Deletes a ticket. Responses: 204 with no body; 404 if missing.

## Validation error format
FastAPI returns validation errors in this shape:
```json
{
  "detail": [
    { "type": "value_error", "loc": ["body", "title"], "msg": "Value error, title must be at least 3 characters ...", "input": "ab", "ctx": {} }
  ]
}
```

## Rules applied to text fields
- Leading and trailing spaces are removed.
- `title` must be 3–200 characters after trimming.
- Blank `description` or `assignee` values are stored as `null`.
